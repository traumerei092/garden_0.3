# 店舗基本情報編集履歴管理機能

## 概要
店舗の基本情報の変更履歴を追跡・管理し、コミュニティによる品質評価を行う機能です。店舗情報の透明性確保とデータ品質向上を目的として実装されています。

## 機能の背景・目的

### 主要な目的
1. **透明性の確保**: 店舗情報の変更内容と変更者を明確に記録
2. **データ品質の向上**: コミュニティによる評価システムで不適切な編集を抑制
3. **トレーサビリティ**: 情報の信頼性向上のための変更履歴の可視化
4. **ユーザーエンゲージメント**: 編集に対する評価機能でコミュニティ参加を促進

### 解決する課題
- 店舗情報の不正確な編集や意図的な改ざん
- 変更内容の不透明性による信頼性の低下
- 編集者の責任の所在不明
- データ品質管理の自動化

## 技術仕様

### バックエンド構成

#### モデル設計
**ShopEditHistory モデル** (`backend/shops/models.py`)
- 店舗情報の各フィールド変更を個別に記録
- 変更前後の値、変更者、変更日時を保存
- ManyToManyField（店舗タイプ、レイアウト、オプション、支払方法）の変更も追跡

**HistoryEvaluation モデル**
- 編集履歴に対するユーザー評価（GOOD/BAD）
- トグル機能：同じ評価を再度選択すると取り消し
- ユーザーごとに1つの評価のみ許可

#### 管理対象フィールド
以下の店舗基本情報フィールドの変更を追跡：
- `name` (店舗名)
- `zip_code` (郵便番号)
- `address` (住所)
- `prefecture` (都道府県)
- `city` (市区町村)
- `street` (番地)
- `building` (建物名)
- `capacity` (収容人数)
- `phone_number` (電話番号)
- `access` (アクセス情報)
- `budget_weekday_min/max` (平日予算)
- `budget_weekend_min/max` (週末予算)
- `budget_note` (予算備考)
- `shop_types` (店舗タイプ - ManyToMany)
- `shop_layouts` (店舗レイアウト - ManyToMany)
- `shop_options` (店舗オプション - ManyToMany)
- `payment_methods` (支払方法 - ManyToMany)

#### API設計
```
GET /api/shops/{id}/edit-history/ - 編集履歴取得
POST /api/history/{history_id}/evaluate/ - 履歴評価
```

### フロントエンド構成

#### コンポーネント構造
**ShopHistoryModal** (`frontend/src/components/Shop/ShopHistoryModal/`)
- 編集履歴の表示・評価機能
- ユーザーフレンドリーな表示名への変換
- 評価ボタン（Good/Bad）のトグル機能

#### フィールド表示名管理
**fieldLabels.ts** (`frontend/src/utils/fieldLabels.ts`)
- データベースのカラム名をユーザーフレンドリーな日本語表示名に変換
- 変更内容のフォーマット処理
- "None"や空値の適切な表示処理

## UI/UX設計方針

### デザイン原則
1. **コンパクトレイアウト**: 情報を効率的に表示し、余計な余白を削減
2. **視覚的階層**: 変更内容と評価ボタンの明確な分離
3. **アクセシビリティ**: カラーコントラストとユーザビリティの確保
4. **一貫性**: プロジェクト全体のカラールールに準拠

### カラー設計
- Good評価: `rgba(0, 198, 255, 1)` (第二強調色)
- Bad評価: `rgba(235, 14, 242, 1)` (カスタム色)
- アクティブ状態: fill色での視覚的フィードバック
- ホバー効果: 背景色の透明度調整

### インタラクション設計
- **トグル評価**: 同じボタンを再押しで評価取り消し
- **リアルタイム更新**: 評価後の即座なカウント更新
- **ユーザーリンク**: 編集者・作成者への適切なプロフィールリンク

## 実装の要点

### シリアライザー設計
- `ReviewAuthorSerializer`の使用でuid含む完全なユーザー情報を提供
- コンテキスト情報を活用したuser_evaluation の動的取得
- ManyToManyFieldの名前リスト化による可読性向上

### 履歴追跡の実装
- `ShopUpdateAPIView`でのフィールド変更検出
- ManyToManyFieldの変更前後比較アルゴリズム
- 変更があった場合のみ履歴レコード作成

### エラーハンドリング
- API通信エラーの適切な表示
- 認証エラーの処理
- データ不整合時の fallback 表示
